# Package Install Check

公開した Core / Standard / Analyzers を NuGet.org から取得し、ビルド・起動と Analyzer の診断を確認する CI 用プロジェクトです。
通常開発で未公開バージョンの復元や意図的な診断が発生しないよう、`InteractionFlow.slnx` には含めません。

## 実行

`NuGet` ワークフローの公開成功後に、同じリリースのコミットで `Package Install Check` を実行します。
GitHub Actions から手動実行も可能です。公開済みのバージョンを指定しているタグまたはブランチを選択してください。
検証だけを再実行する場合、パッケージの再公開は不要です。

バージョンはルートの `Directory.Build.props` から読み込み、三つのパッケージを完全一致で参照します。
公開用の認証情報は使用せず、取得元を NuGet.org に限定し、ランナーの一時ディレクトリに専用のパッケージ保存先を作成します。

## 公開後の取得待ち

`.github/scripts/Restore-PublishedPackages.ps1` が直ちに復元を試み、失敗した場合は5分間隔で再試行します。
初回から60分、初回を含む最大13回を上限とし、最後の試行の復元処理自体は期限を超えて完了する場合があります。
ジョブ全体のタイムアウトは75分です。

再試行中は専用保存先を保持し、取得済みパッケージを再利用します。HTTP キャッシュは使用しません。
復元失敗の原因は分類せず再試行するため、設定不備も上限まで再試行されます。
途中の復元失敗は通常ログに残し、最終的に復元できなければ検証失敗とします。

## 確認内容

1. 解決したパッケージのバージョンをログとジョブサマリーへ出力する。
2. `InteractionFlowArchitecture001` を抑制してビルドし、プログラムを起動する。
3. 抑制せず再ビルドし、ビルド失敗と `error InteractionFlowArchitecture001` を確認する。

`Entities/CheckEntity.cs` の Port 参照は、Analyzer の動作を確認するための意図的な違反です。
このプロジェクトを単独で IDE に開いた場合は診断が出ます。
プログラムは `Hello, World!` を表示するだけであり、ライブラリ API の動作検証は行いません。
復元後のビルド・起動・診断確認の失敗は再試行しません。

このドキュメントは、README の Philosophy 節を補足しつつ、README とは独立して、Interaction Flow の「世界観」を説明する文章です。
なぜこの考え方に至ったのか、ソフトウェアとは、そして相互作用の流れ（Interaction Flow）とは何なのか、など、 README では拾えない考えの詳細を説明します。

## Interaction Flow は、ソフトウェアから始まったものではない

Interaction Flow Architecture の出発点は、既存のソフトウェアアーキテクチャを改善することではありませんでした。

その出発点は、現実に存在する相互作用の観察とモデル化です。

人は環境に働きかけます。
環境は反応します。
その結果、人は状況を理解し、その理解を前提として次の行動を選択します。

この循環は、人と人との会話でも、道具の利用でも、ゲームでも、そして生物と環境との相互作用でも見られます。

Interaction Flow Architecture は、この普遍的な「相互作用の流れ」をソフトウェアへ写像したものです。

---

## ソフトウェアは、相互作用の一つの形である

一般に、ソフトウェアは画面や機能、あるいはデータ処理として捉えられます。

しかし利用者が実際に経験しているのは、それらではありません。

利用者が経験しているのは、

* 何を行えるのか
* システムはどう応えるのか
* その結果、何が変わるのか
* 次に何ができるようになるのか

という、一連の相互作用です。

Interaction Flow Architecture は、ソフトウェアを機能の集合としてではなく、相互作用を継続する存在として捉えます。

---

## Context Loop は、「関係の歴史」である

Context は単なる状態ではありません。

それは Context Loop の一瞬を切り取ったものであり、
ユーザーとシステムが共有している「現在」です。

同じ画面でも、
同じ入力でも、
そこへ至る過程が違えば、Context Loop は異なります。

ここで異なっているのは、画面や入力の状態ではなく、ユーザーがその瞬間をどのように体験するかです。

現在の Context は、相互作用によって次の Context へ進み続けることで、
ユーザーとシステムの関係として積み重なっていきます。

Interaction Flow Architecture が重視しているのは、その積み重なりかたです。

Context Loop は、Interaction の流れが育む *「関係の歴史」* なのです。

---

## コードは、相互作用を記述するための言語である

ソフトウェア開発では、コードは処理を書くためのものだと考えられがちです。

Interaction Flow Architecture は少し違います。

コードとは、

**ユーザーとシステムの関係を設計するための言語**

であると考えます。

Interaction があり、
Operation があり、
Reaction があり、
Context が更新される。

その流れを設計することが、ユーザー体験を設計することになります。

---

## 良いアーキテクチャは、良い関係を育てる

Interaction Flow Architecture が目指しているのは、コードを美しくすることではありません。

コードの構造と、ユーザーが経験する構造を近づけることです。

責務が明確になれば、実装だけでなく体験も理解しやすくなります。

責務の漏れは、体験の違和感として現れます。

開発者はコードを改善することで、ユーザーとの関係を改善できます。

開発の品質とユーザー体験の品質は、別々に存在するものではありません。

同じ構造の異なる側面です。

---

## 「相互作用の流れ」という視点

Interaction Flow Architecture は、ソフトウェアを設計するためのアーキテクチャです。

しかし、そのモデルは現実の相互作用から生まれています。

そのため、この視点はソフトウェアだけに閉じません。

人と人とのコミュニケーション。

AIエージェント同士の協調。

利用者自身が持つ行動の流れ。

あるいは、生物と環境との関係。

Interaction Flow は、それらを説明する理論ではありません。

しかし、それらを

**「相互作用の流れ」**

として考えるための、一つの視点を提供できるかもしれません。

---

## おわりに

Interaction Flow Architecture の真の目的は、新しいデザインパターンを作ることではありません。

ソフトウェアを、外界と関係を築き続けるシステムとして捉え直すこと。

そして、その関係を、コードによって直接設計できるようにすること。

それが、このアーキテクチャの思想です。

そしてこの思想が、ソフトウェアの世界を従来より少し自由にしてくれることを信じています。

> **世界は体験され、体験は Interaction の流れによって歴史として育まれる。
> ソフトウェアもまた、そんな世界の一つである。**

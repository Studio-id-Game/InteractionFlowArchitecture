# EscapeGameの責務整理: 旧プランの扱い

状態: 旧プランは、入力と不変ゲーム状態を共有する再実装へ置き換え済み。
以前の受付情報拡張・ルール注入方式による段階計画を、今後の実装指示として適用しない。

[現在の実装と同期契約](./ESCAPE_GAME_GAMEPLAY_RULES.md)を参照する。

## 今回の到達点

- WorldRulesはGameplayに属し、入力の解釈、ゲーム状態・ポーズ・省略の規則を扱う。
- EscapeAccessは入力とゲーム状態を同期し、ゲーム規則や表示変換を持たない。
- 不変GameStateをUpdateGameStateで一括反映し、取得済みの状態を変更しない。
- 文言・ボタン状態・演出時間はViewへ移した。
- Contextはアクセス範囲を提供し、状態変換や実行管理を担当しない。

## 残る判断

現時点で、旧プランに沿った追加の責務移動は必要ない。
ゲーム内容が増えた段階でGameStateの内部構造化を検討する。
入力の一件配送と最新制御要求で不足する場合は、そのゲーム仕様に合わせて蓄積方針を決める。
提示完了の信頼境界はViewにあり、同期側が実描画・ユーザーの認識を保証する機構は追加しない。

変更を重ねる前に、今回の単純なデータ共有モデルの読みやすさと使いやすさを確認する。

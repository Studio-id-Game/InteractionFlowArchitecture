# EscapeGameのテスト点検

確認日: 2026-11-11。対象は現在のEscapeGameとその既存テストです。
行カバレッジ率ではなく、公開する契約・観測できる振る舞いとテストの対応を確認しました。
型の配置やフィールド代入そのものを固定するテストは追加していません。

## 現在の検証範囲

| 責務 | 主なテスト | 確認する内容 |
| --- | --- | --- |
| ゲーム規則 | DomainTests | 解法、勝敗、鍵消費、扉、無効操作とターン消費 |
| 状態共有・入力受付 | SharedGameStateTests / AccessTests | 不変取得、排他更新、拒否時の応答、二重待機、取消、セッション分離 |
| 提示・再開待機 | AccessTests / GameplayReactionTests | 現行キー照合、提示完了前の進行拒否、ポーズ、停止、待機の取消 |
| 反映結果とInteraction | GameplayReactionTests / ResultInteractionTests | 無効操作と前提違反の区別、結果提示後の入力受付、リトライ、失敗時の打ち切り |
| フレーム・View | FrameTests / WindowReactionStateTests | 入力の優先順位、配送後の描画、文言、ボタン、演出時計とポーズ境界 |
| Context・Lifetime | ContextTests / LifetimeAccessTests | 契約の公開範囲、追加値の制約、Cancellation共有、破棄、停止と再公開拒否 |
| 終了・失敗の集約 | CleanupTests / FailureTests / FlowTests | 先行失敗の保持、キャンセルの扱い、集約順序、停止失敗後も合流・閉鎖すること |
| 全体の接続 | FlowTests | 初期提示、12ターンの解法、リトライ、段階境界の取消、描画とゲーム進行の並行実行 |

## 不足していた確認への対応

- 提示を置換・解除したとき、旧待機がStoppedになり、古いキーを受理しないことを追加した。
  置換では、GameStateを変更しなくても新しいキーが発行され、スキップ要求がリセットされることも確認する。
- 一つの提示待機をキャンセルしても、別の待機者や後からの完了待機が影響を受けないことを追加した。
- 制御入力が最新一件だけ保持され、取り出しで消費され、セッション終了・全体停止で破棄されることを追加した。
- 全体停止の既存テストに実際の提示待機を加え、入力・提示・再開の三つを同時に解除することを確認した。
- フレーム入力の既存テストを補強し、終了優先、ポーズとスキップの競合、提示キーの配送、描画前の配送を確認した。

追加ケースは6件、既存ケースの補強は上記のとおり。EscapeGameは129件から135件になった。

## 重複・過剰な固定の判断

同じ入力待機フラグを連続で確認していた重複assertを一つ削除した。
それ以外の単体・フロー間の重なりは、確認する境界が異なるため維持した。

- DomainTestsの解法はゲーム規則を確認し、FlowTestsの解法は非同期の接続・提示・終了・再試行を確認する。
- AccessTestsの古いキー拒否は共有アクセスを確認し、FrameTestsは制御要求の配送・消費経路も確認する。
- FailureTestsは例外の同一性・順序を確認し、CleanupTestsは終了用ContextとHandlerの連携を確認する。
- 補助クラスの配置・内部メンバーごとのテストや、recordの生成・withの動作を繰り返すテストは追加しない。

## 確認方法と限界

全体ビルドは警告・エラー0件。全体テストはEscapeGame135件と他470件の全605件が成功した。
今回の修正対象はテストと文書だけで、製品コードは変更しない。
ネイティブ描画・実キーボード操作の再確認や、任意のスレッド実行順序を網羅した証明は今回の範囲に含まない。
描画を代替したフローとViewの変換・時計を検証している。

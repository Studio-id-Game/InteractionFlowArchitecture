# Interaction Flow Architecture - Overview

本ドキュメントは、Interaction Flow Architecture における全体構造の概要をテキストとして表現したものである。

## 概要

このアーキテクチャは、システムを「フロー単位」で分解し、
ユーザーの目的達成と内部処理を明確に分離する構造を持つ。

---

## 外部主体（User）

以下のような存在を「User」として扱う：

- 人間
- 上位システム
- エージェント
- 他システム
- etc...

※ ユーザーには、自動化されたエージェントなどの他システムも含まれる

---

## システム構成

### System / Application / Service

システムは以下の2つの観点で構成される：

- **Layers（層）**
- **Blocks（構成要素）**

---

## Layers（レイヤー）

### 1. Focus Layer
- ユーザーの目的を達成するためのフロー単位
- 外部から見える意味的な処理単位

---

### 2. Interaction Layer
- システム内部の目的を達成するためのフロー単位
- Focus を構成する内部的な処理単位

---

### 3. Function Port Layer
- 依存関係を逆転させるための抽象インターフェース
- 外部依存を切り離す境界

---

### 4. Function External Layer
- 実際の処理を行う外部依存の実装
- インフラ・技術的詳細を担う

---

## Blocks（構成ブロック）

### 1. Focus Builder Block
- Focus を構築するための仕組み
- DIコンテナのラッパーとして機能する

---

### 2. Domain Block
- システムの前提となるデータ構造の定義
- ビジネスロジックの基盤

---

### 3. External Block
- 選定された技術プール
- 具体的には以下を含む：

  - 外部ライブラリ
  - OS
  - フレームワーク

---

## キー概念まとめ

- **Focus**: ユーザー視点の意味単位
- **Interaction**: 内部処理の構成単位
- **Port**: 抽象化された境界
- **External**: 技術的実装
- **Block**: 各責務を担う構成単位
